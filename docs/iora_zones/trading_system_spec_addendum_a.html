A.1The Core Insight — One Engine, Every Level

The base spec defines zone roles (push, continuation, pullback, reversal) and the parent-child cascade. This addendum formalizes the key realization: every structural relationship in the system is a triplet of three consecutive timeframes running the exact same state machine.

The Universal Triplet

At every level of the cascade, the same three-actor pattern applies:

Parent creates a zone → Child pushes to break the parent zone boundary → Grandchild confirms or denies the child's push through its own push/pull cycle.

This pattern is instantiated 6 times across the 8-TF cascade. Each instance runs independently but feeds into adjacent instances. The system is nothing more than 6 copies of the same engine, connected in series.

This means:

  • There is one set of rules to define, not per-TF logic
  • Every TF participates in up to 3 triplets simultaneously — as parent, as child, and as grandchild
  • Direction flows downward through the triplets (parent → child → grandchild)
  • Confirmation flows upward (grandchild → child → parent)
  • The automation system implements one engine and parameterizes it 6 times

A.2The Universal Triplet — Formal Definition

Triplet Inputs

Triplet Definition
Triplet(P, C, G) where:
  P = Parent timeframe
  C = Child timeframe  (one level below P)
  G = Grandchild timeframe (one level below C, two below P)

Inputs at runtime:
  P.last_zone      → The last zone created on the parent TF
  P.last_zone.type → Supply or Demand
  P.last_zone.class → HH, LH, HL, LL
  P.push_zone      → The child zone that initiated the parent's last HH/LL
  C.zones[]        → All active child zones inside the parent's current structure
  G.zones[]        → All active grandchild zones inside the child's current structure

Triplet State Machine

At any moment, a triplet is in exactly one of four states. The state describes what the child is doing relative to the parent:

State
Child Activity
Grandchild Role
Bias
PUSHING
Child zones push in parent's direction. Creating zones to break parent zone boundary.
Grandchild confirms child push via its own push/continuation zones.
Trade with parent direction. Every child zone in parent's direction = entry opportunity.
CONTINUING
Child has made push zone + continuation zones. Extending HH higher / LL lower.
Grandchild drives each continuation leg. Pullbacks within continuation are normal.
Trade with parent direction. Continuation zones = structure stacking, trend healthy.
PULLING BACK
Child zones push counter to parent direction. Moving back toward parent push zone.
Grandchild drives the pullback. G's push/continuation = C's pullback depth.
Trade counter to parent direction at child level. Each child pullback zone = entry in pullback direction. But — parent direction resumes once pullback resolves.
REVERSING
Child has broken parent's structural level (LH/HL). New parent leg forming.
Grandchild CHoCH confirmed the child's structural break.
Parent direction has changed. Reversal zone = origin of new parent leg. All lower triplets re-evaluate.

Transition Detail — PULLING BACK → PUSHING (Resolution A)

Pullback reaches push zone

Price reaches the parent's push zone. The pullback is complete. The child zone that forms at the push zone (the demand/supply that reverses price from here) becomes the new push zone for the next parent leg — if a new parent HH/LL is subsequently made.

Grandchild confirmation required: the grandchild must show CHoCH in the child's pullback direction (exhaustion of the pullback) before the new push is confirmed.

Transition Detail — PULLING BACK → PUSHING (Resolution B)

Last pullback zone broken

The last child pullback zone is body-close broken before price reaches the push zone. This means the pullback has been rejected. The child zone that drove the break becomes the new push zone in the parent's direction — the parent push is extending without having fully retraced.

Grandchild confirmation required: the grandchild must show CHoCH against the child's pullback direction (reversing the pullback) before the new push is confirmed.

Transition Detail — PULLING BACK → REVERSING

Grandchild breaks parent structure

The grandchild zones driving the pullback break through the parent's LH supply (if parent was bullish) or HL demand (if parent was bearish). At this point:

  • The pullback is no longer a pullback — it has broken parent structure
  • The child zone that drove the break = REVERSAL zone
  • A new parent leg (LH or HL) begins from the reversal zone
  • The parent TF will create a new zone from this leg
  • All triplets below re-evaluate (cascading direction change)

A.3The Six Triplet Instances

The 8-TF cascade (MN → W → D → H4 → H1 → M15 → M5 → M1) produces exactly 6 triplet instances. Each one is a copy of the same engine from section A.2, parameterized with three consecutive TFs:

T1 Macro Structure
PARENT MN — Monthly zones set ultimate boundaries
CHILD W — Weekly pushes inside MN zones to make/break MN structure
GRAND D — Daily confirms/denies Weekly push via its own push/pull
T2 Macro Direction
PARENT W — Weekly zones set directional frame
CHILD D — Daily pushes inside W zones to make/break W structure
GRAND H4 — H4 confirms/denies Daily push
T3 Swing Structure
PARENT D — Daily zones set swing boundaries
CHILD H4 — H4 pushes inside D zones to make/break D structure
GRAND H1 — H1 confirms/denies H4 push
T4 Intraday Structure
PARENT H4 — H4 zones set intraday boundaries
CHILD H1 — H1 pushes inside H4 zones to make/break H4 structure
GRAND M15 — M15 confirms/denies H1 push
T5 Execution Structure
PARENT H1 — H1 zones set execution boundaries
CHILD M15 — M15 pushes inside H1 zones to make/break H1 structure
GRAND M5 — M5 confirms/denies M15 push
T6 Micro Execution
PARENT M15 — M15 zones set micro boundaries
CHILD M5 — M5 pushes inside M15 zones to make/break M15 structure
GRAND M1 — M1 confirms/denies M5 push
Boundary cases: MN has no parent (it is the ultimate anchor — its zones are taken as given). M1 has no grandchild (it is the lowest resolution — its push/pull state is confirmed by its own internal HA transitions only, no deeper confirmation available).

A.4Cascade Connectivity — How Triplets Feed Each Other

The six triplets are not independent — they are connected in a chain. Each TF participates in up to 3 triplets simultaneously, playing a different role in each. This creates two directional flows:

Downward Flow: Direction Cascade

Direction flows down

When a parent creates a new zone, it sets the direction for the child. The child's job is to push toward that parent zone's boundary. This cascades:

MN creates zone
  → W must push to break MN zone boundary
    → D must push to break W zone boundary (to fulfill W's push)
      → H4 must push to break D zone boundary (to fulfill D's push)
        → H1 must push to break H4 zone boundary
          → M15 must push to break H1 zone boundary
            → M5 must push to break M15 zone boundary
              → M1 drives M5's push

Each level's "push" is simultaneously fulfilling its parent's structural move AND setting the target for its child.

Upward Flow: Confirmation Cascade

Confirmation flows up

When a grandchild shows CHoCH, it confirms the child's push is exhausting. This feeds upward:

M1 CHoCH
  → Confirms M5 push exhausting (T6 grandchild signal)
    → M5 reversal feeds into M15 structure (T5 grandchild signal)
      → M15 reversal feeds into H1 structure (T4 grandchild signal)
        → H1 reversal feeds into H4 structure (T3 grandchild signal)
          → H4 reversal feeds into D structure (T2 grandchild signal)
            → D reversal feeds into W structure (T1 grandchild signal)
              → W reversal = MN structural event

A reversal at M1 doesn't instantly reverse MN — it propagates upward through each triplet, and each level must independently confirm the reversal before it feeds higher. This creates natural dampening — noise at lower TFs is filtered out before it reaches higher TFs.

Critical Property — Cascading Confirmation

A reversal at triplet T(n) only affects triplet T(n-1) if the reversal propagates through the intermediate TF. Example:

H1 CHoCH (T4 grandchild) → confirms H4 pullback direction → but this does NOT automatically reverse D unless H4's move subsequently breaks D's structural zone. Each triplet is a gatekeeper.

A.6Full Cascade Read — Mechanical Procedure

This is the procedure the automation system executes on every new zone event, at any TF. It produces the current directional bias, target, and confidence for each triplet.

Step 1: Identify the Event

ON: New zone created at TF X
    zone.type = SUPPLY or DEMAND
    zone.class = HH, LH, HL, or LL

Step 2: Determine Which Triplets Are Affected

TF X participates in up to 3 triplets:
  - As PARENT in triplet where X = P  →  update: what is child doing inside X's new zone?
  - As CHILD in triplet where X = C   →  update: what role does X's new zone play in parent's structure?
  - As GRANDCHILD in triplet where X = G → update: does X's new zone confirm/deny child's push?

Step 3: Update Each Affected Triplet's State

State Update Logic (per triplet)
IF new zone is on CHILD TF:
  
  IF zone is INSIDE parent's current zone:
    IF zone direction ALIGNS with parent direction:
      IF no push zone exists yet → state = PUSHING, this zone = push zone
      IF push zone exists AND zone extends HH/LL → state = CONTINUING
    IF zone direction is COUNTER to parent:
      state = PULLING BACK, this zone = pullback zone

  IF zone BREAKS parent zone boundary (body close through):
    Parent structural event: new HH/LL confirmed
    Push zone for this leg = confirmed
    Parent TF updates its own zone sequence

IF new zone is on GRANDCHILD TF:

  IF grandchild shows CHoCH against child's current direction:
    IF child is PUSHING or CONTINUING:
      Early warning: child push may be exhausting
    IF child is PULLING BACK:
      Pullback exhaustion signal — watch for pullback resolution
  
  IF grandchild breaks PARENT's structural zone (LH/HL):
    state = REVERSING
    Child zone that drove the break = reversal zone
    Parent leg changes: new HL or LH forming

Step 4: Derive Bias and Targets

Triplet StateBiasTargetConfirmation Needed
PUSHING Parent direction Parent zone boundary (top for bullish, bottom for bearish) Grandchild maintaining push/continuation
CONTINUING Parent direction Next parent zone boundary or previous parent extreme Grandchild maintaining push/continuation
PULLING BACK Counter to parent Parent push zone (the magnet pulling price back) Grandchild driving pullback; watch for G CHoCH as exhaustion signal
REVERSING Counter to parent (new parent direction forming) Reversal zone = origin of new leg Confirmed — grandchild already broke parent structure

Step 5: Composite Bias

The trading bias is the alignment of all 6 triplets. Maximum confidence when all triplets agree. Conflicting states = caution or no-trade.

Alignment Rules

Full alignment (highest confidence): T1 through T6 all in PUSHING or CONTINUING in the same direction. Every TF confirms the move.

Partial alignment (tradeable with caution): Higher triplets (T1-T3) aligned, lower triplets (T4-T6) may show pullback. Trade in higher TF direction, using lower TF pullback zones as entries.

Conflicting (no trade or reduced size): Higher triplets show PULLING BACK or REVERSING while lower triplets push. Structure is in transition.

A.8Automation Data Model

This section defines the data structures needed to implement the universal triplet engine in code. This is the bridge between the conceptual spec and the indicator/automation build.

Zone Object

{
  id:           string      // unique zone identifier
  tf:           TF          // MN, W, D, H4, H1, M15, M5, M1
  type:         "supply" | "demand"
  class:        "HH" | "LH" | "HL" | "LL"
  top:          float       // zone top price
  bottom:       float       // zone bottom price
  created_bar:  int         // bar index at creation
  created_time: datetime    // timestamp of creation
  status:       "active" | "broken" | "expired"
  broken_by:    "body_close" | "expired" | "overflow" | null
}

Triplet State Object

{
  triplet_id:       "T1" | "T2" | "T3" | "T4" | "T5" | "T6"
  parent_tf:        TF
  child_tf:         TF
  grandchild_tf:    TF

  // Current state
  state:            "PUSHING" | "CONTINUING" | "PULLING_BACK" | "REVERSING"
  direction:        "bullish" | "bearish"

  // Zone references
  parent_zone:      Zone      // the parent zone that defines this triplet's boundaries
  push_zone:        Zone | null   // the child zone that initiated the push
  continuation_zones: Zone[]  // child zones extending the push
  pullback_zones:   Zone[]    // child zones pushing counter
  reversal_zone:    Zone | null   // if state = REVERSING

  // Targets
  push_target:      float     // parent zone boundary being pushed toward
  pullback_target:  float     // push zone price (magnet for pullbacks)

  // Confirmation
  grandchild_choch: bool      // has grandchild shown CHoCH?
  grandchild_break: bool      // has grandchild broken parent structure?
}

Event Processing

ON new_zone(tf, zone):
  
  // 1. Find all triplets this TF participates in
  affected_triplets = get_triplets_for_tf(tf)
  
  // 2. Update each affected triplet
  FOR triplet IN affected_triplets:
    IF tf == triplet.child_tf:
      update_child_state(triplet, zone)
    IF tf == triplet.grandchild_tf:
      update_grandchild_confirmation(triplet, zone)
    IF tf == triplet.parent_tf:
      reset_triplet(triplet, zone)  // new parent zone = fresh cycle
  
  // 3. Check cascade effects
  FOR triplet IN affected_triplets:
    IF triplet.state changed to REVERSING:
      propagate_reversal_up(triplet)
    IF triplet.state changed to PUSHING:
      propagate_direction_down(triplet)
  
  // 4. Recalculate composite bias
  update_composite_bias()
